# 운영형 리서치 리포트 수집기

증권사별로 HTML 구조와 인증 방식이 다른 리서치 보고서를 28개 소스에서 수집하고,
중복 제거·정규화·알림까지 처리하는 개인 운영 시스템이다. 2021년 단일 파일에서
모듈형 Python/Docker/PostgreSQL 파이프라인으로 전환해 OCI에서 24/7 운영한다.

## 문제와 설계

- 소스별 차이는 공통 `WebScraper` 경계와 registry로 격리했다.
- 보고서 저장은 `ReportPayload`와 `report_unique_key`를 기준으로 정규화·멱등 처리한다.
- 수집 결과는 manifest 정책과 validator로 빈 결과와 계약 위반을 구분한다.
- CI는 테스트 성공 뒤에만 이미지 빌드와 blue/green 배포를 허용한다.

## 검증과 운영 효과

오프라인 테스트와 계약 테스트를 배포 게이트로 두고, 운영 장애는 읽기 전용 로그
진입점에서 재현 범위를 먼저 좁힌다. watchdog 자기 로그 재알림, DB VIEW startup DDL,
subprocess zombie, 백업 디스크 폭증을 각각 원인 경로와 종료 조건이 보이는 구조로
개선했다. API 키·고객 데이터·운영 주소는 저장소에 포함하지 않는다.

이 프로젝트의 핵심 역량은 크롤러 작성보다 레거시 계약을 보존하면서 데이터 모델,
프로세스 수명, 배포 검증을 단계적으로 개선하고 실제 운영 결과로 확인한 점이다.
